# 明細カテゴリ編集・分類ルール連携 設計

## 背景

明細画面の `取引を編集` モーダルではカテゴリを変更できるが、現在の分類ルールとは
連動していない。そのため、手動で変更したカテゴリは `全明細を再分類` の実行時に
分類ルールの結果で上書きされる。

カテゴリ変更は原則として今後の類似明細にも適用する。一方で、その明細だけを例外的に
変更する操作も残し、例外として固定したカテゴリは再分類から保護する。

## 目的

- 明細のカテゴリ変更から、今後の類似明細へ適用する分類ルールを追加できるようにする。
- 類似明細の条件として、利用者が部分一致キーワードと任意の金融機関を指定できるようにする。
- ルール追加時に、既存ルールの変更や既存明細の一括更新を行わない。
- その明細だけを変更した場合は、全明細再分類でもカテゴリを維持する。
- カテゴリ欄を、ブラウザ依存の `datalist` から明示的な選択UIへ変更する。

## 対象外

- 既存の分類ルールを明細編集から更新または削除する機能
- カテゴリの新規作成、名称変更、削除
- ルール追加直後に、条件へ一致するほかの既存明細を一括更新する機能
- 分類ルールのキーワード部分一致、金融機関完全一致という判定方式の変更

## 基本方針

カテゴリ変更には次の2つのモードを設ける。

1. **分類ルールを追加する**
   - 新しい優先ルールを追加する。
   - 開いている明細だけを選択カテゴリへ直ちに更新する。
   - その明細は手動固定しない。
   - ほかの既存明細はその場では変更せず、今後のインポートまたは全明細再分類で
     新しいルールを適用する。
2. **この明細だけ変更する**
   - 分類ルールを追加しない。
   - 開いている明細を選択カテゴリへ更新し、手動固定する。
   - 全明細再分類は固定された明細をスキップする。

通常の操作は1とし、カテゴリ変更時の `分類ルールを追加して今後の類似明細にも適用`
を初期状態でオンにする。

## データモデル

`transactions` に手動固定状態を表す列を追加する。

```sql
category_locked INTEGER NOT NULL DEFAULT 0
```

- `0`: 分類ルールによる再分類対象
- `1`: 手動カテゴリを固定し、再分類対象外

既存明細と新規インポート明細は既定値の `0` とする。カテゴリ値は既存の
`transactions.category` を引き続き利用し、自動分類値と手動値を別々の列には保存しない。

共有の取引型と明細APIレスポンスにも固定状態を追加する。DB層では
`category_locked`、クライアント向けには真偽値の `categoryLocked` として扱い、
表示側がDBの整数表現へ依存しないようにする。

## 編集モーダル

### 既存項目

- カテゴリは `GET /api/settings/categories` の既存カテゴリを表示するセレクトボックスにする。
- メモは従来どおり自由入力とする。
- メモだけを変更した場合、分類ルール関連の操作は表示せず、固定状態も変更しない。

### カテゴリ変更時

カテゴリを現在値から変更した場合に、次の項目を表示する。

- `分類ルールを追加して今後の類似明細にも適用` チェックボックス
  - 初期状態はオン。
- 適用キーワード
  - 明細の説明文全体を初期値にする。
  - 利用者が部分一致に使う文字列へ編集できる。
- `この金融機関に限定` チェックボックス
  - 明細に金融機関がある場合は初期状態をオンにする。
  - オンの場合は現在の明細の金融機関をルールへ保存する。
  - オフの場合、ルールの金融機関を `NULL` にする。
- 影響確認
  - 指定条件へ一致する既存明細の件数を表示する。
  - 選択中の明細に適用されているルールと、指定条件に関係する競合ルールを表示する。
  - `保存時に変更するのはこの明細のみ。ほかの既存明細には再分類時に反映されます`
    と明記する。

ルール追加をオフにした場合はキーワード、金融機関、影響確認を隠し、
`この明細のカテゴリを固定します。全明細を再分類しても変更されません`
と表示する。

ルール追加がオンの場合は、キーワードが空、キーワードが現在の明細の説明文へ
一致しない、カテゴリ一覧または影響確認の取得に失敗している状態では保存できない。

### 固定状態の表示と解除

固定明細には、明細カードと編集モーダルの両方に `手動固定` バッジを表示する。
編集モーダルに `固定を解除して分類ルールに戻す` 操作を設ける。

固定解除時は固定フラグを外すだけではなく、その時点の最新ルールで対象明細を再分類し、
結果のカテゴリを直ちに保存する。固定明細からカテゴリを変更してルール追加を選んだ場合も、
保存と同時に固定を解除する。

## 影響確認API

明細編集専用の影響確認APIを追加する。

```text
POST /api/transactions/:id/category-rule-preview
```

リクエストは、選択カテゴリ、キーワード、金融機関条件を含む。サーバーは対象明細の存在、
カテゴリが既存カテゴリ一覧に含まれること、キーワードが空でなく対象明細へ部分一致すること、
指定金融機関が対象明細の金融機関と一致することを検証する。

レスポンスは少なくとも次を含む。

- 条件へ一致する既存明細件数
- 現在その明細で優先されるルール
- 新ルールと同時に一致し得る既存ルール
- 同一の有効なルールを再利用できるか

入力変更時は短い待機時間を置いて再取得し、古いリクエストの結果で新しい入力状態を
上書きしない。取得中はその旨を表示する。

## 保存APIと原子性

既存の `PATCH /api/transactions/:id` を拡張し、メモに加えて任意の
`categoryChange` を受け取る。

`categoryChange` は次のいずれかとする。

- `rule`: 選択カテゴリ、キーワード、金融機関条件を含む。
- `fixed`: 選択カテゴリを含む。
- `unlock`: カテゴリ値を含めず、現在の分類ルールへ戻す。

カテゴリを変更していない場合は `categoryChange` を送らない。既存クライアントとの互換性の
ため、現在のカテゴリ・メモ更新形式は直ちに削除しないが、新しい編集モーダルは
`categoryChange` を利用する。

サーバーはプレビューと同じ入力検証を保存時にも行う。ルール追加、明細カテゴリ更新、
固定状態更新、メモ更新はD1の一括処理で実行し、すべて成功するか、すべて失敗するかの
どちらかにする。ルールだけ、または明細だけが更新された状態を残さない。

## 分類ルールの追加

明細編集から既存ルールのカテゴリや条件は変更しない。

同じキーワード、金融機関、カテゴリのルールがすでに存在し、そのルールが対象明細で
競合ルールより優先されている場合は、重複ルールを作らず既存ルールを利用する。
それ以外は新しいルールを追加する。

新ルールの優先度はサーバーが自動決定する。対象明細で現在一致するすべてのルールより
小さい値を設定し、追加したルールが対象明細で確実に優先されるようにする。既存ルールの
優先度や内容は変更しない。異なるカテゴリの同一条件ルールが存在する場合も削除・更新せず、
プレビューで競合を表示したうえで新しい優先ルールを追加する。

保存後に即時更新するのは編集中の明細だけとする。条件へ一致するほかの既存明細は更新しない。

## インポートと全明細再分類

新規インポート明細は従来どおり、保存時点の分類ルールでカテゴリを決める。追加した優先ルールも
同じ分類処理で利用する。

`全明細を再分類` は `category_locked = 1` の明細をスキップし、固定されていない明細だけを
最新ルールで再分類する。レスポンスに次を返す。

- 全明細件数
- 更新件数
- 手動固定のためスキップした件数

設定画面の完了通知にもスキップ件数を表示する。

## エラー処理

- カテゴリ一覧の取得に失敗した場合は再試行を表示し、カテゴリ変更を保存不可にする。
- 影響確認に失敗した場合は入力を維持して再試行を表示する。ルール追加をオンにした保存だけを
  無効にし、ルール追加をオフにした固定保存やメモだけの保存は妨げない。
- 保存に失敗した場合はモーダルと入力を維持し、既存のトーストでエラーを通知する。
- 保存時の検証エラーは、不正な項目を利用者が特定できるメッセージとして返す。
- 対象明細が削除済みの場合は保存せず、一覧を再取得できるエラーとして扱う。
- 一括処理に失敗した場合はルール、カテゴリ、固定状態、メモのいずれも変更しない。

## テスト

### データと分類処理

- マイグレーションにより既存明細が `category_locked = 0` になる。
- 新規インポート明細が固定なしで保存され、追加ルールを利用して分類される。
- 全明細再分類が固定明細を変更せず、スキップ件数を返す。
- 固定解除が最新ルールによるカテゴリを直ちに保存する。
- 優先度の自動決定により新ルールが対象明細で勝つ。
- 既存ルールの内容と優先度を変更しない。
- 再利用可能な同一ルールを重複作成しない。

### API

- プレビューが一致件数、現在の優先ルール、競合ルール、再利用可否を返す。
- 空キーワード、対象明細に一致しないキーワード、不正な金融機関、未知のカテゴリを拒否する。
- `rule`、`fixed`、`unlock` の各保存モードが期待するカテゴリと固定状態を保存する。
- ルール追加と明細更新の一部が失敗した場合に、すべてロールバックされる。
- ルール追加直後に、対象以外の既存明細が変更されない。
- メモだけの既存更新形式が引き続き動作する。

### クライアント

- カテゴリ欄が明示的なセレクトボックスである。
- カテゴリ変更時だけルール設定UIが表示され、初期状態がルール追加オンになる。
- キーワードと金融機関限定の初期値が対象明細から設定される。
- ルール追加オン・オフで入力欄、説明、保存内容が切り替わる。
- 影響件数、競合警告、読み込み、再試行、入力エラーを表示する。
- 固定明細にバッジと固定解除操作を表示する。
- メモだけの編集、キャンセル、削除、保存後の一覧再取得が従来どおり動作する。

### 回帰確認

- 分類ルールの設定画面、CSVインポート、全明細再分類が正常に動作する。
- 月次・年間・割り勘レポートが保存後のカテゴリと固定状態の追加によって壊れない。
- 型検査、単体テスト、プロダクションビルドが成功する。

## 受け入れ条件

- 明細のカテゴリ変更から、利用者が指定したキーワードと任意の金融機関を持つ優先ルールを
  追加できる。
- ルール追加時に編集中の明細だけが直ちに変更され、ほかの既存明細は変更されない。
- 今後のインポートと全明細再分類では追加ルールが利用される。
- 例外として固定した明細は全明細再分類で上書きされない。
- 固定を解除すると、その時点の最新ルールへ戻る。
- 既存ルールは明細編集から変更されない。
- 影響件数と競合ルールを保存前に確認できる。
- ルール追加と明細更新は原子的に保存される。
