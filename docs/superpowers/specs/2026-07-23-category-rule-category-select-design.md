# 分類ルールのカテゴリ選択化 設計

## 目的

設定画面で分類ルールを追加・編集するとき、カテゴリ名を自由入力する代わりに、
保存済みのカテゴリからセレクトボックスで選択できるようにする。
今回の対象には、新規カテゴリを作成する機能は含めない。

## 既存カテゴリの定義

次の3箇所に保存されている、空文字ではないカテゴリ名の和集合を
「既存カテゴリ」とする。

- `category_rules.category`
- `transactions.category`
- `excluded_categories.category`

カテゴリ名は重複を除去し、表示用に昇順で返す。既存データ自体の表記は変更せず、
APIレスポンスでも保存済みの文字列をそのまま使用する。

## APIとデータアクセス

設定APIに `GET /api/settings/categories` を追加する。レスポンスは
`{ items: string[] }` とする。

リポジトリ層に既存カテゴリを取得する関数を追加し、3テーブルを
`UNION` したSQLで重複を除去する。`NULL` と、前後の空白を除くと空になる値は
候補から除外する。並び順はカテゴリ名の昇順とする。

今回の変更ではカテゴリマスターテーブルを新設しない。また、分類ルール作成・更新
APIのリクエスト形式は変更しない。新規カテゴリを入力できない制約は設定画面の
セレクトボックスで実現する。

## クライアント

APIクライアントにカテゴリ一覧取得メソッドを追加する。
`CategoryRulesSection` は分類ルール一覧とカテゴリ一覧をそれぞれ取得する。

追加・編集モーダルではカテゴリのテキスト入力を `select` に置き換える。

- 新規追加時は未選択の「カテゴリを選択」を初期表示する。
- 既存ルールの編集時は、保存済みカテゴリを初期選択する。
- 選択肢はカテゴリ一覧APIが返した値を使用する。
- カテゴリ未選択時は保存せず、既存の必須入力エラーを表示する。
- 保存リクエストには選択されたカテゴリ名をそのまま渡す。

カテゴリ一覧の読み込み中は追加・編集操作を無効にする。取得に失敗した場合は
分類ルール一覧を維持したままエラーと再試行操作を表示し、カテゴリ一覧を取得できる
まで追加・編集操作を無効にする。候補が0件の場合も選択できる値がないため、
追加・編集操作を無効にし、その旨を表示する。

## データフロー

1. 設定画面の表示時に、分類ルール一覧とカテゴリ一覧を並行して取得する。
2. ユーザーが追加または既存ルールを選ぶ。
3. モーダルがカテゴリ一覧をセレクトボックスへ表示する。
4. ユーザーがカテゴリを選択して保存する。
5. 既存の分類ルール作成・更新APIへ、選択値を含むリクエストを送る。
6. 保存成功後、分類ルール一覧とカテゴリ一覧を再取得する。

## エラー処理

- カテゴリ一覧APIの取得失敗は、設定画面内に既存のエラー表示部品で示す。
- 再試行はカテゴリ一覧APIだけを再実行する。
- 分類ルールの保存失敗は、現在と同様にトーストで通知し、モーダルを維持する。
- カテゴリ未選択やキーワード未入力は、API呼び出し前に必須エラーとして通知する。

## テスト

- リポジトリのカテゴリ一覧取得が3テーブルの値を対象にすることを確認する。
- 重複、`NULL`、空文字、空白のみのカテゴリが適切に処理されることを確認する。
- カテゴリ一覧APIが `{ items: string[] }` を返すことを確認する。
- 分類ルールのカテゴリ欄が自由入力ではなくセレクトボックスであることを確認する。
- 新規追加時の未選択状態、編集時の初期値、選択値を保存リクエストへ渡す処理を確認する。
- 既存テスト、TypeScriptの型検査、ビルドを実行して回帰がないことを確認する。

## 対象外

- 新規カテゴリの作成、名称変更、削除
- カテゴリ専用マスターテーブルの追加
- 明細編集画面や除外カテゴリ設定画面の入力方式変更
- 分類ルール作成・更新APIに対するカテゴリ存在チェック
