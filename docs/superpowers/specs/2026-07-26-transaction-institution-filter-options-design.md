# 明細画面の金融機関候補取得 設計

## 背景

明細画面の金融機関セレクトは、表示中の明細ページから候補を作っている。1ページは50件のため、選択月の後半にある金融機関は候補に表示されない。

## 目的

選択中の年月に明細を持つ全金融機関を、ページングやほかの絞り込み条件に関係なく金融機関セレクトへ表示する。

## 対象外

- 明細一覧のページング件数や並び順の変更
- 金融機関による明細絞り込みの仕様変更
- カテゴリ・キーワードに応じた金融機関候補の絞り込み

## 設計

### API

`GET /api/transactions/institutions?year=&month=` を追加する。

- `year` と `month` は必須とし、`month` は1から12のみ許可する。
- `transactions` から指定年月に一致する、空でない金融機関名を重複なく取得する。
- 返却値は名前順に並べた `{ items: string[] }` とする。
- 年月が無効な場合は400を返す。

リポジトリ層には、この取得だけを担当する関数を追加する。明細一覧のページング・カテゴリ・金融機関・キーワード条件は利用しない。

### クライアント

明細画面は選択中の年月が変わるたびに金融機関一覧APIを取得し、その結果をセレクトの選択肢として表示する。

- カテゴリ、金融機関、キーワード、ページ変更では一覧を再取得しない。
- 金融機関フィルタが設定されていても候補一覧は同じ月の全金融機関を維持する。
- 月内に対象明細がない場合は、既存の「全金融機関」だけを表示する。
- 一覧取得に失敗した場合は、既存の画面エラー表示の扱いに合わせて明示的に表示する。明細ページのデータから候補を推測する縮退動作はしない。

### テスト

- リポジトリ/API: 指定月の重複なし・名前順の金融機関一覧を返すこと、別月を含めないこと、無効な年月を400にすること。
- クライアント: 明細ページの先頭50件に存在しない金融機関も、同月の候補として表示されること。
- 回帰: 既存の金融機関フィルタ、カテゴリ・キーワード絞り込み、ページングを維持すること。

## 受け入れ条件

2026年5月の明細画面で、先頭50件にないVIEWカードも金融機関セレクトに表示される。VIEWカードを選択すると、その月のVIEWカード明細のみが表示される。
